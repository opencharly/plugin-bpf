# 2026.293.1013 — feat(skills): move the bpf skill body beside its candy, and stop the bare bpf ignore pattern eating it

## Summary

Moves the `bpf` skill body out of `candy/plugin-bpf/charly.yml` and into
`candy/plugin-bpf/.agents/skills/bpf/SKILL.md` — beside the candy that owns the node, which is where the loader
resolves it — and corrects the `.gitignore` pattern that would otherwise have silently ignored the new file.

**This PR supersedes `opencharly/plugin-bpf#8`**, which the validator auto-closed after five counting verdicts. It is
a clean single commit from `main`, not a continuation of that history.

| | before | after |
|---|---|---|

The diff against `main` is **35 insertions and 29 deletions across three files**.

### Why beside the candy, and why the `.gitignore` change is in this PR

`sdk/deploykit/skills_collect.go` resolves the tree as `filepath.Join(layer.GetSourceDir(), ".agents/skills")`, and
`GetSourceDir()` is the directory of the candy whose manifest declares the node — here `candy/plugin-bpf/`.

`.gitignore` line 1 was a bare `bpf`, which matches a path component of that name at **any depth**. Measured:

```
$ git check-ignore -v .agents/skills/bpf/SKILL.md
.gitignore:1:bpf	.agents/skills/bpf/SKILL.md
```

Without removing it the extracted file is invisible to git and the manifest deletion would ship alone — a body lost
rather than moved. The next line already carries the correctly scoped `/candy/plugin-bpf/bpf`, so the bare duplicate
protected nothing.
